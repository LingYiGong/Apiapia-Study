# 日语学习工具前端 MVP (第一阶段) 需求文档

## 1. 项目概述
本项目是一个基于浏览器的纯前端日语学习 Web 应用。核心理念是**“听力优先”**与**“间隔重复（Spaced Repetition）”**。
在第一阶段（MVP）中，应用完全在浏览器本地运行，无需后端。主要功能包括：单词的手动录入与管理、基于纯听力的每日复习测试，以及利用本地存储（LocalStorage）进行数据持久化。

**目标用户模型：** AI 编程助手。请严格按照以下规范和步骤生成完整、可运行的代码。

## 2. 技术栈要求
*   **前端框架**：Vue 3 (必须使用 Composition API 和 `<script setup>` 语法)。
*   **样式框架**：Tailwind CSS (用于快速构建响应式、极简且现代的 UI)。
*   **数据存储**：浏览器原生 `localStorage`。需封装独立的数据读写服务。
*   **语音引擎**：浏览器原生 `Web Speech API` (`window.speechSynthesis`)。

## 3. 数据结构定义
请在代码中定义并严格遵循以下数据结构（TypeScript 接口规范参考，即使写 JS 也要遵循此数据形态）：

```javascript
// 单词对象结构
{
  id: "1694830000123",    // 唯一标识符 (推荐使用 Date.now().toString())
  word: "先生",           // 日文汉字或假名 (显示主体)
  kana: "せんせい",        // 平假名注音 (Furigana)
  meaning: "老师",        // 中文释义
  level: 0,               // 掌握等级 (0: 新词/未掌握, 1: 熟悉, 2: 掌握...)
  next_review_date: 1694830000123 // 下次复习的时间戳 (毫秒)
}
```
*注：所有单词数据以数组形式存储在 localStorage 的 `ja_vocab_list` 键下。*

## 4. 核心功能模块

应用应包含两个主要视图（可以通过简单的 Tab 切换或路由实现）：**【单词管理】** 和 **【练习模式】**。

### 4.1 单词管理模块 (Word Management)
*   **添加/编辑单词**：提供一个表单，包含三个输入框：日文(word)、注音(kana)、中文意思(meaning)。提交后生成唯一 ID，初始 `level` 设为 `0`，`next_review_date` 设为当前时间，并存入 localStorage。
*   **列表展示**：以列表或表格形式展示所有录入的单词，显示日文、注音、中文和当前状态。
*   **删除功能**：列表每项需提供【删除】按钮，点击后需有二次确认弹窗。

### 4.2 练习模式模块 (Practice Mode - 核心逻辑)
*   **队列初始化**：进入练习页面时，筛选出 `next_review_date` 小于等于当前时间的单词，作为“今日待复习队列”。
*   **前置交互（解决浏览器自动播放限制）**：练习开始前，显示一个巨大的【开始今日练习】按钮。用户点击后才初始化 TTS 引擎并进入测试态（这是为了授权浏览器播放声音）。
*   **状态 1：听力盲测态**
    *   **界面**：隐藏单词文本、注音和中文。只显示一个“播放中/重新播放”图标按钮。
    *   **行为**：自动调用 Web Speech API 朗读当前单词的 `word` 字段。**必须强制设置 `lang = 'ja-JP'`**。
    *   **操作区**：显示两个大按钮：【认识 / 理解】 与 【没理解】。
*   **状态 2：答案揭晓态 (仅点击“没理解”触发)**
    *   **界面**：完整显示该单词的 `word`、`kana` 和 `meaning`。
    *   **操作区**：底部按钮变成唯一的【下一个 (Next)】按钮。
*   **状态机与队列更新逻辑**：
    *   **点击【理解】**：该单词 `level` +1，根据新 level 推迟 `next_review_date`（例如：level 1 推迟 1 天，level 2 推迟 3 天）。保存至 localStorage。从今日队列中移除，**自动朗读**队列中的下一个单词。
    *   **点击【没理解】**：进入“答案揭晓态”。该单词 `level` 降为 0（或保持0）。将其**放回今日队列的末尾**（确保今天必须点一次“理解”才能结束）。
    *   **点击【下一个】**（揭晓态）：界面切回“听力盲测态”，**自动朗读**队列中的下一个单词。
*   **完成状态**：当队列为空时，显示“今日任务已完成”的庆祝提示。

## 5. UI/UX 建议规范
*   **移动端优先 (Mobile-First)**：UI 必须自适应，在手机屏幕上单手操作体验良好。
*   **极简设计**：练习界面不要有任何多余的干扰元素。
*   **大点击区**：【理解】和【没理解】按钮必须占据屏幕下方的绝大部分空间，方便盲操。
*   **视觉反馈**：【理解】建议使用柔和的绿色调，【没理解】使用警示的红色/橙色调。状态切换时避免页面高度剧烈跳动。

## 6. 给 AI 的代码编写指令 (AI System Prompts)
开发本系统时，请遵循以下技术要求：
1.  **组件化**：请使用 Vue 3 组合式 API (`<script setup>`)，将 UI 拆分为逻辑清晰的组件（如 `App.vue`, `ManageView.vue`, `PracticeView.vue`）。如果生成单文件 HTML，请保持代码结构清晰、注释完整。
2.  **TTS 踩坑处理**：
    *   请妥善处理 `window.speechSynthesis.getVoices()` 异步加载的问题，确保能准确拿到 `ja-JP` 的发音人。
    *   在切换单词时，若上一个音频未播完，需调用 `window.speechSynthesis.cancel()` 停止旧音频。
3.  **安全防护**：对 localStorage 的读写操作必须包裹 `try-catch`，防止 JSON 解析错误导致应用崩溃。
4.  **样式实现**：请直接使用 Tailwind CSS 的 Utility Classes 编写样式，无需编写额外的 CSS 文件。
